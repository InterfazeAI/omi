## Overview

Two areas to test on DevKit 2: **SD card storage** (offline audio recording) and **button behavior** (tap events via BLE).

<Warning>
**Never remove the SD card while the device is on.** It is not hot-swappable. Use the safe removal process described below.
</Warning>

---

## SD Card Storage

When the device is disconnected from the phone (LED is red), audio data is written to the SD card instead of streaming over Bluetooth.

### SD Card Commands

Commands are sent as 6-byte packets: `[command, file_number, offset_byte0, offset_byte1, offset_byte2, offset_byte3]`

| Command | Action |
|---------|--------|
| `0` | Read specified file from offset |
| `1` | Clear all bytes in specified file |
| `2` | Clear all files in directory |
| `3` | Stop transmission of specified file |

**Example:** Read file 1 starting at byte 255:
```
[0, 1, 255, 0, 0, 0]
```

### Response Codes

| Code | Meaning |
|------|---------|
| `0` | Command successful |
| `100` | End of file transmission (last byte) |
| `200` | Delete process finished |
| `3` | Invalid file (file 0 never exists; files start at 1) |
| `4` | File size is 0 |
| `6` | Invalid command |

<Note>
If you don't receive code `100` or `200`, the command was not completed.
</Note>

## Testing Process

<Info>
**Prerequisites:** Python packages from `requirements.txt`, plus `opus` for audio decoding (`brew install opus` on macOS). The tools live in [`omi/firmware/scripts/devkit/sd_sync/`](https://github.com/BasedHardware/omi/tree/main/omi/firmware/scripts/devkit/sd_sync). Run them from that directory — they import `omi_sd` as a sibling module.
</Info>

These find the device by service UUID, so there is no device ID to paste in.

<Steps>
  <Step title="Check what is on the card" icon="list">
    ```bash
    python3 info.py
    ```
    Prints the device name, how many bytes are recorded, and roughly how long a full sync would take. If nothing is found, the device is not advertising — see the note below.
  </Step>
  <Step title="Record and download" icon="download">
    ```bash
    python3 record_and_pull.py 60 ~/Desktop/take1.wav
    ```
    Marks the current recording length, waits 60 seconds while you speak near the mic, then downloads exactly that span and decodes it to a playable WAV. Recording continues throughout and the card is not cleared.
  </Step>
  <Step title="Re-decode an earlier span" icon="file-audio">
    ```bash
    python3 pull_range.py <start> <length> ~/Desktop/take2.wav
    ```
    Audio stays on the card until it is overwritten, so you can pull a span again without recording it again.
  </Step>
  <Step title="(Optional) Check sync speed" icon="gauge">
    ```bash
    python3 throughput.py 25
    ```
    Roughly 14–16 KB/s is healthy. Around 0.1 KB/s indicates thread starvation in the firmware rather than a slow card.
  </Step>
  <Step title="(Optional) Delete Audio" icon="trash">
    Run `delete_audio_files.py` from the parent directory — replace the `device_id` value with your device ID. Prefer reading from an offset over deleting: on some firmware revisions the delete command stopped recording until the next reboot.
  </Step>
</Steps>

<Note>
The device only starts advertising after its SD card mounts successfully, so "device not found" usually points at the card rather than the radio.
</Note>

<Warning>
The older scripts in the parent directory — `get_audio_file.py` and `decode_audio.py` — target a previous storage protocol that used 83-byte packets, and fail silently against current firmware, which sends 440-byte blocks. One writes an empty file, the other decodes garbage, and neither reports an error. Use the `sd_sync/` tools above.
</Warning>

## Safe SD Card Removal

<Steps>
  <Step title="Reset the device">
    Double-tap the reset button inside the kit
  </Step>
  <Step title="Remove the SD card">
    Remove the card to inspect contents on your computer
  </Step>
  <Step title="Reinsert and restart">
    Put the SD card back and tap the button to restart
  </Step>
</Steps>

## Device Behavior

| Connection State | LED | SD Card |
|-----------------|-----|---------|
| No Bluetooth | Red | Writing audio to SD card |
| Bluetooth connected | Blue | Stops writing; streams over BLE |

### App-Side SD Card Import

When the device connects to the app with stored audio:

1. A green banner appears showing estimated download time
2. Tap the banner (or go to **Settings → Device Settings → Storage**) to open the import screen
3. Press the download button to start importing — a progress bar shows completion

<Note>
The green banner only appears for DevKit 2 devices. DevKit 1 devices do not support SD card import.
</Note>

## Button Events

After connecting to the BLE notification service, these events fire:

| Event Code | Action |
|------------|--------|
| `1` | Single tap |
| `2` | Double tap |
| `3` | Long press (~3 seconds) |
| `4` | Button pressed down |
| `5` | Button released |

Verify that each physical action sends the correct BLE packet.

## Known Issues

<Accordion title="Empty audio file on SD card (v2.0.1)" icon="bug">
  Some devices create an empty `a01.txt` file, preventing audio from being written.

  **Fix:**
  1. Delete the audio file
  2. Press the reset button to reboot
  3. The device will auto-generate the required files on startup
</Accordion>
